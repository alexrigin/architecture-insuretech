# Проблемы и риски:

1. Работа сервисов core-app и ins-comp-settlement жестко зависит от работы сервисов страховых компаний. Если происходит сбой при вызове сервиса любой страховой компании, то отменяется весь агрегирующий запрос (даже если по 9 компаниям был получен корректный ответ). Если хотя бы один сервис недоступен, то core-app и ins-comp-settlement совсем не получат актуальных данных.
2. Также, например, если core-app и ins-comp-settlement при получении ошибки от ins-product-aggregator, делают повторный запрос (ретрай-логика), то в ситуации, когда недоступен сервис только одной из страховых компаний, все остальные сервисы будут получать дополнительную нагрузку. ins-product-aggregator-у приходится гонять одни и те же данные по несколько раз.
3. Время ответа на запрос в сервис ins-product-aggregator будет расти с появлением большего количества страховых компаний.
4. Чем дольше отвечает ins-product-aggregator, то тем дольше сервисы core-app и ins-comp-settlement блокируют свои ресурсы.
5. Из-за необходимости взаимодействия сервисов по сети с использованием синхронного протокола приложение менее отказоустойчиво.
6. Поскольку данные запрашиваются по расписанию, то зачастую данные в репликах неактуальные. + возникают сложности поддержания согласованного состояния в репликах.
